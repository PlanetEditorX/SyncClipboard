## v10 真机：日志终于上来了

`release/dist/SyncClipboard/log/ios_shortcut.log`：

```
SyncClipboard 同步日志
=== SyncClipboard 同步开始 ===
① 服务器 http://192.168.1.23:8000 ｜ 设备 熊熊的iPhone
② 响应 type=file_list
② 原文 {"status":"ok","files":[{"size":20641972,"kind":"file",…}],"folder_count":0,"type":"file_list"}
③ 待下载 1 项
```

**Log 通到 ③（待下载 1 项）就断了**，后面文件明明下载成功（client.log 里
`获取文件下载 → 取消共享` 都在），但再没有任何日志推上来，最后一条是
`POST /ios_log` 400 + `body='{"log":""}'`。

## 根因：日志累加源指向了「没执行的那条分支」

v10 为了躲开变量，把每条日志都拼在**上一条文本动作的输出**上：

```
日志 = 上一条文本输出 + 新的一行
```

看着稳，其实有个死穴 —— `存盘结果` 那条日志写在「如果 / 否则」里：

```
如果 存盘输出 有任何值 → 文本「OK 写入 …」   ← 存盘成功时执行
否则                 → 文本「保存失败 …」   ← 存盘失败时执行
```

而生成顺序上记住的是**最后造的那条**（失败分支）。存盘成功 → 失败分支没跑
→ 引用是空的 → 推上去的 body 就是 `{"log":""}`。

更要命的是 `400`：iOS 的「获取 URL 内容」**遇到非 2xx 会中断整条快捷指令**，
所以指令不是"跑完了只是没日志"，而是**死在循环里**。

## v11 的两处改动

1. **累加只认「日志」变量**（分支里怎么走，它都是最后被赋的完整内容），
   推送 body 也直接取这个变量 —— 变量出现在文本 token 里是 iOS 自己的标准
   写法，跟分支无关。
2. **服务端空日志回 200 而不是 400**：日志是附属通道，它自己出问题绝不该把
   同步带崩。空日志只记一条 warning，然后正常返回。

## 仍然存在的限制

- **空目录**建不出来（没有文件就没有落点），结尾会提示数量。
- 文件多时「每个文件一次下载 + 一次日志推送」，会慢。
- 多台电脑各登记了目录时无法合并清单，会明确提示「请分开同步」。
