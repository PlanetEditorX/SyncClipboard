## 一、四条反馈的处理

| 反馈 | 处理 |
|---|---|
| 没有内容时说「服务端没有新文本」 | 改成 **「服务端没有新内容」**。文本分支只是「这次没东西」的一种，说「文本」容易让人以为文件丢了 |

## 二、编号为什么放在服务端

快捷指令里要自己累加序号，得靠「计算」动作维护一个变量（初始化 → 每次 +1）。
多一个动作就多一个真机上可能出错的点，而 `计算` 的参数在 iOS 上有坑：加法必须
**整个省略 `WFMathOperation` 键**（写 `+` 会被当成别的运算），写错了不报错、
只是算错。这种地方不值得赌。

所以改成服务端算好塞进响应：

```json
// /request_file 的每个普通文件条目
{"name": "a.pdf", "kind": "file", "index": 3, "total": 10, ...}
// 顶层
{"type": "file_list", "file_count": 10, "folder_count": 0, ...}

// /manifest/batch 的每个目录文件条目
{"name": "a.pdf", "dir": "课程/", "prefix": "课程", "index": 3, "total": 10, ...}
```

编号**只在同类里算**：目录条目不占普通文件的序号，否则一次「2 个文件 + 1 个
目录」的复制会出现 1/3、2/3 这种错位。混合场景有测试盯着。

快捷指令侧只做了降级：`如果 Repeat Item 有任何值(total)` → 显示带序号；否则
退回「正在下载：文件名」。所以电脑端没升级也不会出错，只是没有数字。

- 版本号已改 `common/updater.py` → **1.12.10**，服务端有改动（`file_count`、
  条目 `index`/`total`），需要重新打包才生效。
