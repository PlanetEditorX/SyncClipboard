## 一、日志只在「调试 = 开」时才写

「配置」词典里多了一项：

| 键 | 默认值 | 作用 |
|---|---|---|
| `调试` | **关** | 关：一个日志字节都不产生，也不发 `/ios_log` 请求；开：全流程推日志 |

- 关着的时候，电脑端不会新增/更新 `log/ios_shortcut.log`，手机「下载」也不会
  多出 `SyncClipboard-调试.log`。
- 要排查问题时把它改成「开」再跑一次，我就能在
  `release/dist/SyncClipboard/log/ios_shortcut.log` 里看到全过程。
- 日志累加本身还在内存里做（纯变量拼接，不发请求、不建文件），所以改开之后
  能看到**从第一行开始**的完整过程，不是从打开那一步才开始记。

## 二、平时弹的进度通知

全部是静音通知，会堆在通知中心里，扫一眼就知道进度。和调试开关无关，始终弹。

| 时机 | 通知内容 |
|---|---|
| 拿到内容后 | `开始同步：N 项` |
| 目录有清单时 | `目录 牟立志丨27数量关系夸夸刷复盘笔记：2 个文件` |
| 每个文件下载前 | `正在下载：（第1节）27数量夸夸刷复盘笔记.pdf` |
| 每个文件落盘后 | `已保存 牟立志丨…/（第1节）27数量夸夸刷复盘笔记.pdf` |
| 存盘失败 | `保存失败：X（文件没写进「下载」）` |
| 全部结束 | `同步完成：N 个文件已存入「下载」` |

目录用例里「已保存」带的是 **相对路径**（`目录名/文件名`），不只看名字，还能
顺手确认层级有没有对——这也是之前几轮最容易出错的地方。

## 三、v12 → v13 的实际改动

| 项 | v12 | v13 |
|---|---|---|
| 日志 | 无条件写 | 只在 `调试 = 开` 时写 |
| 中间通知 | 一条不弹 | 每个文件「正在下载 / 已保存」各一条 |
| 开头总览 | 无 | `开始同步：N 项`、`目录 X：N 个文件` |
| 存盘失败 | 只写日志 | 写日志 + 弹通知 |
| 默认主机 | `192.168.1.24` | `192.168.1.23`（与当前电脑端一致） |

## 五、仍然存在的限制

- **空目录**建不出来（没有文件就没有落点），结尾会提示数量。
- 文件多时「每个文件一次下载 + 两条通知」，通知会刷一屏；嫌吵可以把
  「已保存」那条删掉，或把文件拆小批同步。
- 多台电脑各登记了目录时无法合并清单，会明确提示「请分开同步」。
- 电脑端 1.12.6 及以上才有 `prefix` 字段；更旧的版本退回 `dir + "/"` 拼接，
  多一个斜杠 iOS 会合并，层级仍然对。
