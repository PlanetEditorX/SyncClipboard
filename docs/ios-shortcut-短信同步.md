# iOS 快捷指令：短信同步

验证码短信到手 → 自动抽出那串数字 → 推给电脑端（`POST /ios/sync`）→ 电脑剪贴板
里就是它，网页上直接粘贴。短信进来时手机顺带复制一份，自己手动粘也行。

手机端只导入 `短信同步.shortcut` 这一份；另外在「快捷指令 → 自动化」里加一条
「收到信息时」的自动化指向它，**自动化不写进产物**（原因见「触发怎么配」）。

## 它和另外两份的分工

| | 触发方式 | 干什么 | 验证码短信来了会怎样 |
|---|---|---|---|
| 获取同步 | 手动点 | 从电脑拉文件 | 无关 |
| 文字同步 | 「打开 App 时」自动化，驻留轮询 | 双向对剪贴板 | **同步不到**：它只在某个 App 前台时跑，而验证码短信多半在人没动手机、或者刚切到电脑上时到 |
| 短信同步（本份） | 「收到信息时」自动化，一条短信一次 | 抽验证码 → 推给电脑 | 这才是它存在的理由：事件驱动，不等你回到手机上 |

## 原来那份草稿的问题

草稿是手搭的 10 个动作：匹配 → 取组 1 → 如果 有值 → 复制到剪贴板 → 配置词典 →
主机可达？→ 如果 是 是 → **运行「发送文件」** → 结束如果 → 结束如果。
逻辑骨架对，但整条链路没有一处真的把验证码送到电脑上。

| # | 位置 | 问题 | 后果 |
|---|---|---|---|
| 1 | 正则第二分支 `([A-Za-z0-9]{4,6})…(?:验证码…)$` | 只取了**组 1**，而「数字在前」的句式命中的是**组 2** | 「123456 是您的登录验证码」这类**一半的短信静默失败**：有动作、无结果 |
| 2 | 正则第一分支 `[\s是是为：:]*([A-Za-z0-9]{4,6})` | 捕获组后面没有边界 | `验证码123456789` 截成 `123456`；`验证码：2026年11月…` 把年份 `2026` 当验证码 |
| 3 | 正则第二分支 `([A-Za-z0-9]{4,6})` | 左边没有边界 | 从订单号 / 金额一串数字中间截 4–6 位 |
| 4 | 关键词表只有 `验证码 / 校验码 / 动态码` | 少 `代码`（Apple 的短信就是「代码：123456」）、`确认码`、`安全码`、`口令`、`code / OTP` | 这些短信一条都抽不到 |
| 5 | `{4,6}` | 上限 6 位 | 8 位码被截成 6 位，推过去的是错的 |
| 6 | `如果 文本 有任何值` | 单条件形态（`WFCondition: 100`）。repo 里踩过：iOS 只认表模板形态（`WFConditions`），单条件导入后标红「请为此操作中的每个参数选取值」，跑到这里整条指令中断 | 可能直接断在半路。iOS 自己导出的这份也是单条件形态，所以也可能只是导出时省略了默认值；真机若标红就改成表模板 —— 生成版用的就是表模板 |
| 7 | `如果 主机可达 是 是 → 运行「发送文件」` | 推给电脑的那一步是**调另一条叫「发送文件」的快捷指令**，而那条是「把手机文件传到电脑下载目录」 | 验证码根本没进 `/ios/sync` 链路；还平白依赖一条无关的快捷指令存在 |
| 8 | 「不可达」分支 | 空的 | 电脑没开 / 不在同一网段时验证码直接丢掉，不提示、不暂存 |
| 9 | 词典里的 `密钥` | 从没被用过 | 密钥是摆设；真去请求时服务端一律 403，表现成「无法连接到服务器」 |
| 10 | 没有 `source` | 服务端 `clients` 表里没有这台设备 | 判重与回投都失效，文字同步那边也跟着漂 |
| 11 | 没有探活之外的处理、没有日志 | — | 出问题时手上什么都没有 |
| 12 | 触发条件「信息 包含 …」 | 导出的 `WFMessageConditions` 里 `Values` 是**空的**（只剩 `Property: Message` / `Operator: 1`） | 要么对每条短信都跑、要么压根不触发，取决于 iOS 怎么解释空值；建议在自动化里把值显式填上（见下） |
| 13 | 复制到剪贴板在推送之前、且无开关 | — | 推送失败也照样改你剪贴板；想关只能手删动作 |

## 重构后的流程

```text
取正文（快捷指令输入）
  └ 没有输入（多半是手动点运行）→ 记日志 → 停
匹配 A：关键词在前  验证码：123456 / 校验码为 8888 / code is 654321
  └ 命中 → 取组 1
  └ 没命中 → 匹配 B：数字在前  123456 是您的登录验证码 → 取组 1
  └ 还是空 → 记日志 → 停（这不是验证码短信）
探活 /status
  └ 不可达 → 验证码写进「存储内容」(验证码待发) → 通知(可选) → 停
  └ 可达   → 有「验证码待发」就先补推，清空
POST /ios/sync {key, content: 验证码, source: 设备名}
  └ 回包 status = ok  → 复制到剪贴板(可选) → 通知(可选) → 日志
  └ 其它              → 写进「验证码待发」 → 通知(可选) → 日志
```

114 个动作（含注释与日志分支）。动作数多不怕，怕的是判断路径绕 —— 这里每个
`如果` 都只判一件事：有没有抽到、在不在线、回包成不成。

### 几个刻意的取舍

| 决定 | 为什么 |
|---|---|
| 推的是**验证码本身**，不是整条短信 | 电脑端要的是能直接粘进输入框的那串。整条短信里的「【某某】」「5 分钟内有效」粘过去全是噪音 |
| 抽到之后**复制到手机剪贴板**（可关） | 人在手机边上时直接粘；关掉就只在电脑上，手机不留痕 |
| **不记验证码到日志** | 验证码是凭据，落进日志文件等于多一处泄漏面。日志只记「抽到几位 / 推送成不成」 |
| 不可达时**暂存一条**，下次补推 | 验证码短信经常在你不在家（手机流量、电脑没开）时到。「不可达」是常态之一，不该等于丢掉 |
| 只用**一个**捕获组，不写组号 | 「获取匹配中的组」不写 `WFMatchGroupIndex` 时默认取组 1（iOS 自己导出的那份也没有这个键，App 里显示「组 1」）。两个分支各只有一组，直接拿输出，不必碰那个类型对不上账的参数 |
| A、B 两条模式分开跑，而不是一条大正则 | 两个方向的关键词关系互斥，写进一条会互相回溯；分开后每条都能加自己的边界，且 B 只在 A 落空时执行 |

## 配置词典

导入后点「配置」直接改，改完不用重新签。全是**文本**：写成数字/布尔，在「如果」
里会显示成空白，判据恒不成立。

| 键 | 默认 | 说明 |
|---|---|---|
| `协议` | `http` | 拼地址 `协议://主机:端口` |
| `主机` | `192.168.1.23` | 与电脑端 `config/server_config.json` 的 `host` 一致 |
| `端口` | `8000` | 电脑端监听端口 |
| `密钥` | `123456` | 与电脑端一致；进请求头 `key` 和 body `key` |
| `复制` | `开` | 开 = 推送成功后复制到手机剪贴板；关 = 只在电脑上 |
| `通知` | `开` | 开 = 成功/失败各弹一条（成功那条里带验证码，能直接照着敲）；关 = 静默 |
| `调试` | `关` | 开 = 每次运行把日志 POST 到 `/ios_log`，覆盖写电脑端 `log/ios_shortcut.log` |

正则与关键词不在词典里，它是 `lib/sms.py` 里的代码常量：改完要重跑 `build.py` +
`sign.py` 重新导入，别在 App 里手改（手改的那份下次重签就没了）。

## 触发怎么配（自动化「带不进」文件，只能手加一次）

`.shortcut` 里只有快捷指令本体（`WFWorkflowActions` 那一串）。「收到信息时」这种
**个人自动化存在 Shortcuts 自己的自动化库里**，没有任何 plist 键能表达它 ——
`WFWorkflowTriggers` 是老式触发（手表 / 主屏幕那套），不等于个人自动化，写上它
也不会凭空多出一条自动化。iOS 至今也没给「导入自动化」的入口，第三方 App
（含 Actions）同样造不出来。所以这一步必须手点，换手机、重装都还得重配。

关键的一点：**条件是必填项 —— 不能留空，也没有删除入口**（真机 iOS 26 验证：
条件空着，整条自动化根本不会触发）。所以关键词必须填一个，它管的是「跑不跑」，
跟「抽不抽得出验证码」是两件事。

| 填法 | 结果 |
|---|---|
| 条件留空 / 想删掉这一行 | **不行**：条件空了自动化不触发 |
| 只填 `码`（推荐） | 一个词覆盖 验证码 / 校验码 / 动态码 / 代码 / 密码 / 确认码 / 安全码 |
| 只填 `验证` | 漏「您的 Apple 代码为：123456」「您的动态密码是…」这类一个「验证」字都没有的短信 |
| 加第二个词（`码` + `code`） | 只有能把条件切成「任一」时才可行。多条默认是**「全部满足」（AND）**，两个词各占一行 = 要求同一条短信同时含两个词，几乎永不命中 |

收尾三步：下一步选「运行快捷指令」→ `短信同步`；**关掉「运行前询问」**；保存。

宁可宽、不要窄：关键词只决定「这条短信值不值得跑一次」，多跑一次的代价是几十毫秒
和一行内存日志（不出网、不弹通知、不动剪贴板）；漏触发则是验证码永远到不了电脑。

（值必须显式填。草稿导出的条件里 `Values` 是空的，只剩 `Property: Message` /
`Operator: 1`，空值条件下 iOS 是「全中」还是「全不中」没有保证 —— 真机看就是
压根不触发。）

## 编辑器顶部那块「从 无处 接收 App 和其他 18 个」

它不是动作，是这条快捷指令的**输入声明**，所以没有「删除」可用 —— 它由几个
工作流级键渲染出来，根本不在 `WFWorkflowActions` 里：

| 显示 | 来源键 | 含义 |
|---|---|---|
| `接收 App 和其他 18 个` | `WFWorkflowInputContentItemClasses`（列了 19 类） | 接受任何类型的输入：文本 / 图片 / PDF / URL / 联系人… |
| `从 无处` | `WFWorkflowTypes` 里没有 `WFWorkflowTypeActionExtension` | 没挂进分享表单，所以没有「从某个 App 分享进来」的来源；输入只可能来自自动化或别的指令 |
| `如果没有输入：继续` | `WFWorkflowNoInputBehavior`（本产物没写，iOS 按默认「继续」显示） | 没带输入时不报错、照常往下跑；第 3 步那条「正文没有任何值」会拦住并记一行日志再退 |
| 「快捷指令输入」变量能选 | `WFWorkflowHasShortcutInputVariables = true` | 自动化把短信当输入传进来，指令就靠它取正文 |

**删不得**：去掉输入声明等于这条指令不收输入，`快捷指令输入` 变量随之消失，
自动化传进来的正文也就拿不到。真嫌字多可以点「App 和其他 18 个」把类型收窄
（例如只留文本），但短信是以「信息」内容项传进来的，收窄后要靠 iOS 自己转换，
风险大于收益 —— 建议留着不动。它不占步骤、不影响运行，只是编辑器顶部的一行说明。

## 服务端契约

| 接口 | 用途 |
|---|---|
| `POST /ios/sync` | 上行。body `{key, content, source}`，回 `{status, latest_global}` |
| `GET /status` | 探活，200 即在线（可达性检查用） |
| `POST /ios_log` | 收日志：覆盖写 `log/ios_shortcut.log`；判定为新一次运行时先把上一份挪成 `.1` |

`source` 用设备名，**和文字同步同一个**：服务端按 `clients[source]` 记「这台设备
手上已经是哪份内容」，同名才认得出是同一台设备。名字不同会变成两条客户端记录，
判重、回投都跟着错位。

推上去的内容走服务端的正常路径：`build_text_item` → `copy_text_to_clipboard` →
`notify_clients`，所以电脑端会像收到一次普通复制那样弹出来。手机自己推的这份不会
再回投给手机（`source` 相同）。

文字同步那边可能把同一个验证码再上行一次（它读到的剪贴板变了）；服务端按
「该设备手上已经是这份内容」判掉，不会多一条历史。

## 正则：两条模式，正面和反面都要过

实现在 `shortcuts/lib/sms.py`，真机上跑的是同一份字符串（`tests/test_sms_code.py`
在电脑上跑同一套用例，改了先跑它）。

```regex
A  (?:验证码|校验码|动态码|验证代码|确认码|安全码|短信密码|动态密码|验证口令|口令|代码|[Cc]ode|OTP|PIN)
   (?:[^0-9A-Za-z]|[Ii][Ss]){0,12}([0-9]{4,8})(?![0-9年月日时分秒])

B  (?<![0-9A-Za-z])([0-9]{5,8})(?![0-9])[^0-9A-Za-z]{0,8}
   (?:验证码|校验码|…)
```

| 设计点 | 作用 |
|---|---|
| A 的间隔只允许「非字母数字」或单个 `is`，且**不允许出现数字** | 「验证码有效期5分钟，11月23日」这类句子里的 5 / 11 / 23 不会被当候选 |
| A 的间隔上限 12 | 够跨过「请勿泄露给任何人，」这种插入语，又不至于跑到下一句去 |
| `(?![0-9年月日时分秒])` | `验证码123456789` 不截前 6 位；`有效期至2026年` 不把年份当码 |
| B 的左边界 `(?<![0-9A-Za-z])` | 不从一长串数字中间截一段 |
| B 的下限 5 位 | 4 位在前、后面又跟关键词的写法极少见，而「支付1234元后可获取验证码」正好会把 1234 误当码 |
| 只认 4–8 位**纯数字** | 带字母的码占比太低，放宽到字母后「验证码获取失败 Please retry」会命中 `Please` |

已覆盖的句式（`tests/test_sms_code.py`：13 条正面 + 9 条反面）：银行带金额、
`为 / 是 / ： / 换行` 各种连接、插入语、8 位码、`123456 是您的验证码`、Apple 的
`代码：`、英文 `code is`。

## 日志怎么读

`调试` = 开 时每次运行推一次（事件型，一条短信一次请求，量很小），写进电脑端
`log/ios_shortcut.log`。一次正常的长这样：

```text
=== 短信同步开始 ===
地址 http://192.168.1.23:8000 ｜ 复制 开 ｜ 通知 开
设备 iPhone ｜ 正文 63 字
④ 抽到验证码（6 位，内容不记日志）
⑥ 已复制到手机剪贴板
=== 短信同步结束 ===
⑥ 推送成功
```

| 看到 | 说明 |
|---|---|
| 一个字都没有 | 自动化没配、没关「运行前询问」，或关键词没命中（条件空着同样不触发） |
| 「没有输入」但确实是收到短信自动跑的 | 自动化把「信息」内容项传进来了，而第 3 步只做了「文本」渲染。改成「从输入获取文本」（`is.workflow.actions.detect.text`）再重签；小概率是自动化根本没绑定成功 |
| 「没有输入」且是手动点运行 | 正常：这条指令只该由自动化跑，手动运行拿不到短信正文 |
| 「正文里没抽到验证码」 | 先排除自动化条件过窄（`信息包含 验证` 会漏「代码：123456」）。确属句式问题，再把那条短信抄进 `tests/test_sms_code.py` 的用例，改 `lib/sms.py` |
| 「电脑端不可达 → 暂存」 | 查地址/端口/同网段/服务有没有在跑。验证码已存，下次运行会补推 |
| 「推送失败：回包 status = error」 | 多半是密钥不一致（服务端 403）；也可能是服务端版本过旧没有 `/ios/sync` |

## 构建

```bash
python shortcuts/短信同步/build.py                                    # 生成 plist
python shortcuts/lib/verify.py shortcuts/短信同步/短信同步-unsigned.plist
python shortcuts/lib/sign.py shortcuts/短信同步/短信同步-unsigned.plist
python -m unittest tests.test_sms_code -v                             # 正则用例（2 例 / 22 句）
python -m unittest tests.test_smoke_e2e.TestSmsSyncArtifact -v         # 产物约束（7 例）
```

当前产物：114 个动作，断裂引用 `none`，控制流异常 `none`，可疑参数 `none`，
条件缺参数 `none`；全量回归 `361 tests OK`。

`TestSmsSyncArtifact` 锁的是最容易退化、又最难在电脑上看出来的几件事：产物里的
正则必须就是 `lib/sms.py` 那两条（且各只有一个捕获组）、不许有循环与等待、不许
「运行另一条快捷指令」转发、推送必须打 `/ios/sync` 且 body 带 `key / content /
source`、暂存必须在补推之前读出来。

## 已知限制

- **依赖 Actions**（`IsReachableIntent`）做探活。没装这个 App 的话换成「获取 URL
  内容」探 `/status`，代价是断网时那一步会抛错中断（暂存就不生效了）。
- **关键词是中文 + 少量英文**。`Your verification code has been sent: 123456` 这种
  关键词与数字之间夹别的单词的句子抽不到；要支持就再加一条模式。
- **全角数字不匹配**（`１２３４５６`），真实短信里几乎见不到。
- **只推第一组命中**。一条短信里出现两个码（「旧码 111111，新码 222222」）时取靠前
  的那个。
- **暂存只存一条**。连续两条短信都在离线状态到达时，后一条覆盖前一条 —— 验证码本来
  就一分钟内过时，存队列没意义。
- **推送成功但电脑端没弹**：先看电脑端服务在不在、`text_sync_mode` 是不是「只发送」，
  再确认 `source` 与文字同步是同一个设备名。
