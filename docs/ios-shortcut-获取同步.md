# iOS 快捷指令：获取同步

手机端从电脑拉取「最新一次复制」的内容：文字直接进剪贴板，文件按目录结构逐个
下载到「下载」。手机端只需导入 `获取同步.shortcut` 这一份。

## 目录结构

```
shortcuts/
├── lib/                     ← 所有快捷指令共用的部分
│   ├── sc.py                SC 动作工厂 + token 序列化助手 + DEFAULT_META
│   ├── sign.py              签名：python lib/sign.py <x-unsigned.plist> [输出路径]
│   └── verify.py            校验：python lib/verify.py <plist>
└── 获取同步/                 ← 一个快捷指令一个子目录
    ├── build.py             生成器（改逻辑改这里，别手改 plist）
    ├── 获取同步-unsigned.plist   生成物（未签名，别直接导入 iOS）
    └── 获取同步.shortcut          已签名，导入手机的就是它
```

以后加**短信同步 / 推送同步**时，照这个形状新建子目录：
`短信同步/build.py` 只管流程，动作工厂从 `lib/sc.py` 拿，签名和校验直接用
`lib/` 里那两个脚本 —— 不用再复制一遍工具。

轮询驻留型的 `文字同步/` 已经按这个形状落地，它的动作（读剪贴板 / 存储内容 /
可达性 / 循环计数 / 计算表达式 / 调用自己）都在 `lib/sc.py` 里，见
`docs/ios-shortcut-文字同步.md`。

## 日常操作

```bash
python shortcuts/获取同步/build.py                                  # 生成 plist
python shortcuts/lib/verify.py shortcuts/获取同步/获取同步-unsigned.plist  # 校验
python shortcuts/lib/sign.py shortcuts/获取同步/获取同步-unsigned.plist    # 签名
```

产物名不带版本号：**目录里永远只有当前这一版**，要回看旧版用 `git log`。
签名后的快捷指令名取自 plist 文件名（去掉 `-unsigned.plist`），也就是「获取同步」。

## 手机端行为

### 进度通知（默认，始终弹）

静音通知，堆在通知中心里。

| 时机 | 内容 |
|---|---|
| 拿到内容 | `开始同步：共 N 项` |
| 目录清单 | `目录 牟立志丨27数量关系夸夸刷复盘笔记：共 2 个文件` |
| 每个文件下载前 | `正在下载 第 3/10 个：文件名` |
| 落盘成功 | `已保存 目录名/文件名` |
| 落盘失败 | `保存失败：文件名（文件没写进「下载」）` |
| 全部结束 | `同步完成：N 个文件已存入「下载」` |
| 没内容 | `服务端没有新内容` |

### 日志（配置里「调试」= 开 才写）

默认**关**：不发请求、不建文件、不覆盖任何东西。改成「开」后，每个节点把累积
后的完整日志 `POST /ios_log` 过去，服务端覆盖写：

```
release/dist/SyncClipboard/log/ios_shortcut.log
```

排查完记得改回「关」。

## 配置词典

快捷指令开头有个「配置」词典，导入后可在快捷指令 App 里直接改：

| 键 | 默认 | 说明 |
|---|---|---|
| `协议` | `http` | |
| `主机` | `192.168.1.23` | 电脑端地址 |
| `端口` | `8000` | 服务端口 |
| `密钥` | `123456` | 与电脑端 `server_config.json` 一致 |
| `根子路径` | 空 | 落盘子路径前缀；若多出一层「下载」，填 `下载/` |
| `调试` | `关` | 开 = 写日志；关 = 只弹进度通知 |

## 服务端契约（拉取相关）

**统一鉴权**：`/request_file`、合并清单、每个文件的下载地址，以及调试日志推送，**全部带 `key` 请求头**。发送端 FileServer 已无免密路由，漏带会拿到 403，快捷指令会把那段 JSON 当成文件内容存进「下载」。升级后 4 条快捷指令要一起重新签名导入。

| 接口 | 用途 |
|---|---|
| `POST /request_file` | 一次性拉取。返回 `type`（text / file_list / folder）、`files`、`manifest_batch_url`、`folder_count`、`file_count` |
| `GET /manifest/batch?ids=a,b` | 多目录合并清单，`entries` 一层摊平，每条带 `dir` / `prefix` / `url` / `index` / `total` |
| `GET /file/<id>/<相对路径>` | 单文件下载，不撤销共享 |
| `POST /ios_log` | 收 iOS 日志，覆盖写 `log/ios_shortcut.log`；空 body 回 200 + `skipped` |

普通文件的条目同样带 `index` / `total`（编号只在文件这一类里算，目录不占序号），
手机端据此弹「第 3/10 个」。通知里的项数取服务端 `file_count`（只数普通文件），
不再用 `count(files)` 把目录也算成一项；目录的文件数由清单单独给出。

## 设计约束（改之前先看这几条）

1. **循环深度恒为 1**：iOS 的「重复每一项」嵌套时，内层取到的 Repeat Item 会落到
   外层条目上，字段取到空值。所以服务端把多目录合并成一张清单，快捷指令里是两段
   **并列**的单层循环。
2. **全程不做数字比较**：`如果 X 大于 0` 遇到空值（字段不存在）会弹「请为此操作中
   的每个参数选取值」并**中断整条指令**。判断「有没有内容」一律用「有任何值」。
3. **子路径用「字面斜杠 + 不带斜杠的 prefix」拼**：「存储到文件」会先规范化路径，
   变量值结尾的 `/` 会被吃掉，`目录名/` 于是整串变成文件名，多个文件互相覆盖。
4. **日志累加只认「日志」变量**：用「上一条文本动作的输出」当累加源会在分支里断链
   —— 两条分支只执行一条，另一条动作没跑，引用就是空的。`b.text()` 返回的是 UUID
   字符串，必须 `act_out()` 包一层，否则变量被赋成空值。
5. **附属通道不能拖垮主流程**：`/ios_log` 空 body 必须回 200，非 2xx 会让 iOS
   的「获取 URL 内容」中断整条指令。
6. **不走打包/解压**：iOS 的解压缩会把包内目录摊平，目录只能走清单逐文件下载。

## 已知限制

- **空目录**建不出来（没有文件就没有落点），结尾只提示数量。
- 文件多时通知会刷一屏（每文件两条），且逐文件请求较慢。
- 多台电脑各登记了目录时无法合并清单，会提示「请分开同步」。
- 签名走第三方 HubSign（工作流全文含内网地址与密钥会发过去），偶发
  `RemoteDisconnected`，重试即可。
