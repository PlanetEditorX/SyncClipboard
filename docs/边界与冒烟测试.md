## 边界测试：喂了什么、期望什么

判据只有两条：**不许 500**、**不许产出不可用的下载地址**。第二条比第一条重要 ——
接收端拿着 `http://ip:0/file/xxx` 去下载，看起来像网络问题，实际是发送端写坏了。

### 端口（`TestPortNormalization`，11 例）

`data.get("port", 8899)` 在「键存在、值为 `None`」时不回落默认值，只做 `or` 兜底
也不够：`"0"`、`"abc"`、`-1`、`65536` 全是 truthy。

| 输入 | 旧行为 | 现在 |
|---|---|---|
| `None` / 缺失 / `""` | 8899（`or` 兜底） | 8899 |
| `"0"` | **原样落库 → `http://ip:0/...`** | 8899 |
| `"abc"` / `-1` / `65536` / `3.14` / `True` | **原样落库** | 8899 |
| `" 8899 "`（带空格字符串） | 原样落库成字符串 | 转成 int 8899 |
| `1` / `65535` / `8899` | 保留 | 保留 |

新增 `normalize_file_port()`，所有脏值端到端验证过最终 URL 的 `parsed.port == 8899`。

> 写入侧（`/file_sync`）**必须**收敛，否则整批文件消失；读取侧（`/request_file`）
> **不猜**，脏端口记录整条跳过 —— 发送端的文件服务未必在默认端口上，猜错了比
> 「拉不到」更难查。这条区别由 `test_dirty_port_record_is_skipped_not_guessed` 和
> 既有的 `test_record_without_port_is_skipped` 一起锁住。

### `file_list` 的形状（`TestFileListPayload`，9 例）

| 场景 | 旧行为 | 现在 |
|---|---|---|
| `file_list: ""` / `[]` | 400 | 400，**且不清空已有记录** |
| 没有 body / 非 JSON | **500**（`data.get` 打在 None 上） | 400 |
| `file_list` 是对象 `{...}` | **500**（遍历 dict 拿 key 当条目，`.get` 炸） | 400 |
| `file_list` 是字符串 | 逐字符当记录，全部记失败 | 400 |
| 数组里混 `"垃圾"` / `42` / `null` | **500** | 跳过并计入 `error_count` |
| 整批都不完整（缺 `file_id`） | 200 + 回落文本 | 200 + 回落文本（不 500） |
| `size: null` / `size: 5GB` | — | 正常序列化，大数不丢精度 |

### 文本投递（`TestTextDeliveryBoundary`，7 例）

| 场景 | 期望 |
|---|---|
| 没有 `latest_global` | `{"pasted": true}` |
| `source` 为 `null` | `{"pasted": true}`，不投递也不污染 `clients` 表 |
| `content` 为 `""` | 第一次照发，第二次空（手机侧另有「有任何值」判断） |
| `IOS_NOTIFY` 有推送记录 | 优先返回并消费，消费后回落到全局最新 |
| 同一段文字换了 id | 仍然不重复投递（判重按内容） |
| 新内容 | 再次投递 |

### 记录读侧与客户端端口（14 例）

`/request_file` 的 key 错误、无 body、记录缺 `ip`、脏端口混批、一次性消费；
客户端 `_share_port()` 的三级兜底（`file_server.port` → 配置 → 8899），
含 `port=0` 这种「代表没就绪」的 falsy 值。

## 冒烟测试：真起服务跑完整链路

不打桩传输层，两个 werkzeug 实例通过 socket 对话：

```
电脑端 FileServer（werkzeug，随机端口）
     ↑ /file_sync、/request_file
中心服务 flask_app（werkzeug，随机端口）
     ↑ requests（扮演手机端快捷指令）
```

| 用例 | 验证的事 |
|---|---|
| `test_folder_end_to_end` | 目录 → 拉取（`type=folder`）→ 取 `/manifest/batch` 合并清单 → 逐文件下载 → 落盘路径带出 `课程资料/子目录/` → 再拉一次只剩文本 |
| `test_mixed_files_and_folders` | 目录 + 文件混合时 `type=file_list`（不能报 folder，否则顶层只有一份清单地址、会漏掉普通文件），两种都下得下来 |
| `test_keep_for_retry_reannounces` | 下载中断 → 保留共享 → 重登记 → **再拉一次拿得到** → 完整下完 40 个文件 |
| `test_abrupt_client_close_keeps_share` | 真 RST 断流 → 触发「保留以便重试」，共享没被当成已下完删掉 |
| `test_text_pull_once` | 无文件时退化成文本，且只投递一次 |
| `test_signed_bundle_is_valid` | `.shortcut` 是 `AEA1` + `bvx2` 容器，体积正常 |
| `test_no_archive_or_polling_left` | 产物里没有再出现 `unzip` / `delay` / `repeat.count`：打包与轮询已彻底移除 |
| `test_every_save_has_input_folder_and_subpath` | 每个「存储到文件」都有输入、目标目录；目录分支还必须有以 `/` 收尾的子路径 |

产物类用例读的是真实交付物 `shortcuts/获取同步/获取同步-unsigned.plist` 与
`获取同步.shortcut`；还没生成时自动跳过，不会把「没构建」误报成失败。

## 踩过的坑

**1. `requests` 的 `close()` 造不出断流。**
`stream=True` 读 1KB 就 `close()`，三次里两次不触发服务端失败分支：服务端
往往已经把内容整个写进 socket 缓冲、判定为「发完了」。改成裸 socket 发请求后
`setsockopt(SO_LINGER=0)` 再关，强制 RST，服务端下一次 write 必然失败。

**2. 用目录造断流是无效的。**
目录走 zip，40 个 `"x" * 100000` 压完只剩几十 KB，一次 write 就发完了。
要造断流必须用**不可压缩的大文件**（`os.urandom(8MB)`）。

**3. 异步登记的时序抖动。**
`_keep_for_retry` 在后台线程里 POST，没有完成信号。测试里先断言「线程被唤起」
（回调事件），再同步调一次 `reannounce_shares()` 断言「登记请求本身正确」，
把两件事拆开。改之前偶发红，改之后连跑 8 次全绿。

**4. 空推送会误清别人的共享。**
`latest_file.clear()` 在循环前执行，所以 `file_list` 为空时必须在 `clear()` **之前**
返回 400。这条现在有 `test_empty_list_keeps_existing_records` 守着。

## 怎么跑

```bash
# 全量（含冒烟，约 20 秒）
python -m unittest discover -s tests

# 只跑边界（0.06 秒，改服务端接口时先跑这个）
python -m unittest tests.test_edge_cases

# 只跑冒烟（11 秒，改传输/打包/登记逻辑时跑）
python -m unittest tests.test_smoke_e2e
```

冒烟会真绑定端口并从 `127.0.0.1` 发请求，防火墙拦截本地回环时会失败。

## 仍然修不了的两处

| # | 场景 | 为什么 |
|---|---|---|
| 1 | 共享被撤销 / 超 TTL 时 `/manifest` 返回 404 | iOS「获取URL内容」遇非 2xx 直接抛错，读不到我们写的 `{"status":"error","message":…}`。快捷指令没有 try/catch，只能靠「别把共享留到过期」（默认 30 分钟 TTL）来规避。 |
| 2 | 电脑关机 / 断网 | 网络层异常，同样没有 try/catch，只有系统级报错。需要友好提示只能插回 Actions 的「主机是否可达」。 |
