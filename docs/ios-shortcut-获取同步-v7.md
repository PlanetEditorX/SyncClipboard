> v6 的问题见下面「根因一」。v6 产物保留，但**不要再用**。

## 根因一：子路径末尾的 `/` 被 iOS 规范化吃掉

v6 的保存动作是这么给的：

```
子路径 = 根子路径 + Repeat Item.dir      // dir 形如 "课程/子目录/"，末尾带 "/"
```

`WFFileDestinationPath`（UI 上叫 Subpath）的语义是**路径本身**：末尾有 `/` 时最后一段是目录，iOS 自己补文件名；没有 `/` 时整串被当成**文件名**。真机上变量值结尾的 `/` 在规范化时被吃掉，`课程/子目录/` 退化成 `课程/子目录`，于是：

- 每个文件都被存成名字为「课程/子目录」的文件；
- 加上覆盖开关，后一个覆盖前一个；
- 最终「下载」里只剩一个叫「目录名」的无扩展名文件，一个目录都没建出来。

这正是用户看到的现象：「不能创建目录，而是不停把目录名字作为文件的名字，最后只保留一个」。

## 修法：斜杠改成字面字符，服务端多给一个 `prefix`

服务端 `/manifest/batch` 每条多一个字段：

```json
{"name": "a.txt", "dir": "课程/子目录/", "prefix": "课程/子目录", "url": "…"}
```

- `dir`：保留原样（末尾带 `/`），给 GUI 和旧客户端用；
- `prefix`：同一路径**去掉末尾斜杠**，且保证非空（根目录下的文件也会带根目录名）。

快捷指令不再依赖变量值的末尾字符，斜杠由**字面文本**提供：

```
目标路径 = 根子路径 + Repeat Item.prefix + "/" + Repeat Item.name
        = ""      + "课程/子目录"       + "/" + "a.txt"
        = 课程/子目录/a.txt
```

字面斜杠不受 iOS 路径规范化影响，这是这次真正的修法。

兼容性：清单里没有 `prefix`（电脑端 ≤ 1.12.5）时，退回 `根子路径 + dir + "/" + name`，多出的一个斜杠 iOS 会自己合并，层级仍然正确 —— 但**强烈建议把电脑端升到 1.12.6**。

## 根因二（需求）：调试信息从通知改成日志文件

v6 的调试 = 开时每个步骤弹一条通知，几十条堆在通知中心里翻不动，而且真机崩掉时看不到完整上下文。v7 改成：

- 调试 = 开：全程**不弹中间通知**，把每一步攒成文本，落进

  ```
  下载/SyncClipboard-调试.log
  ```

  固定文件名，每次覆盖；每处理完一个文件就落一次盘，所以即使崩在下一个文件，已经发生的事都在文件里。

- 调试 = 关：不写日志文件，只留结尾一条汇总通知。

日志长这样：

```
=== SyncClipboard 同步开始 ===
① 服务器 http://192.168.1.24:8000 ｜ 设备 iPhone
② 响应 type=folder
③ 待下载 1 项
④ 清单 课程 ｜ 5 个文件 ｜ 空目录 1
· a.txt ｜ dir=课程/子目录/ ｜ prefix=课程/子目录
   OK 写入 课程/子目录/a.txt
· readme.txt ｜ dir=课程/ ｜ prefix=课程
   !! 保存失败（动作输出为空，文件没落地）readme.txt
⑤ 同步结束：5 个文件
```

排查顺序：先看 `④` 的清单数字对不对 → 再看每条的 `prefix` 前缀对不对 → 再看每条的 `OK / !!` 。哪一条开始出现 `!!`，就是那一条的目标路径有问题。

## 仍然存在的限制

- **空目录**建不出来（没有文件就没有落点），结尾会提示「N 个空目录没有文件可写」。
- 文件多时每个文件一次请求 + 一次日志落盘，会慢；清单超 20000 条会截断并提示拆目录。
- 日志文件是「整份覆盖写」：多次运行只留最后一次。要对比两次，先把日志改名。
