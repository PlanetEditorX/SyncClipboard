## 真机现象（v8）

跑完弹窗 `请为此操作中的每个参数选取值。`，红标的动作是：
`如果 目录数 大于 0`（数字框是空的）。整个快捷指令就停在这里，后面的
「同步完成」通知、日志落盘全都没跑。

同一次运行里 `POST /ios_log` 连续 5 次全是 **400**，电脑上没有任何日志。

## 原因一：数字比较碰上「取不到的值」会直接中断

v8 判断「这次带没带目录」用的是：

```
目录数 = 响应.folder_count
如果 目录数 > 0
```

`folder_count` 是服务端后加的字段，只要这一版响应里没有它（版本差异、
请求走了别的分支、返回体不是文件结构……），`目录数` 就是**空的**。iOS 在
数字比较里拿到空值，不会当 0 处理，而是把「比较目标」判成没选值 —— 弹
`请为此操作中的每个参数选取值` 并**中止整条指令**。这就是「跑到一半就没了、
还没有日志」的原因：连收尾的日志推送都没执行到。

**v9 的做法：整条指令里一个数字比较都不留。**

| 原来 | 现在 |
|---|---|
| `如果 文件数量 > 0` | `如果 文件列表 有任何值` |
| `如果 清单文件数 > 0` | `如果 清单.entries 有任何值` |
| `如果 空目录数 > 0` | `如果 清单.empty_dirs 有任何值` |
| `如果 目录数 > 0` + 两层嵌套 | `如果 有 manifest_batch_error` → 显示原文；否则 `如果 类型 是 folder` → 提示升级 |

「有任何值」遇到空值走假分支，**不报错、不中断**，这正是我们想要的语义。
数量（`文件数量` / `清单文件数` / `空目录数`）仍然算出来写进日志，只是不再
参与判断。

## 原因二：日志为什么 400

`/ios_log` 校验的是 `Content-Type: application/json` + `{"log": "..."}`。真机
上连着 5 次 400，说明 iOS 这侧发的正文形状和预期不一致（「获取 URL 内容」在
参数组合稍有出入时会改发原始正文）。

v9 双管齐下：

- **服务端宽容**：JSON 里有 `log`/`text` 就取字段；正文不是 JSON 就**把正文
  本身当日志写盘**，并 `logging.warning` 记下 content-type 和 body 前 300 字
  —— 下次再出问题，`log/server.log` 里能直接看到 iOS 到底发了什么。
- **快捷指令加一行诊断**：拉取后把原始返回体整份写进日志（`② 原文 {...}`），
  有没有 `manifest_batch_url` / `manifest_batch_error` 一眼可见，不用再猜版本。

## 日志在哪

```
<程序目录>\log\ios_shortcut.log
```

打包版就是 `release/dist/SyncClipboard/log/ios_shortcut.log`（`BASE_DIR` 取
exe 所在目录）；源码直跑则是项目根下的 `log/`。每个节点推一次**累积后的
完整日志**，崩在哪一步，文件就停在哪一步。

## 仍然存在的限制

- **空目录**建不出来（没有文件就没有落点），结尾会提示数量。
- 文件多时「每个文件一次下载 + 一次日志推送」，会慢。
- 多台电脑各登记了目录时无法合并清单，会明确提示「请分开同步」。
