## v7 真机结论：目录结构已经对了

两条反馈：

- 「当前目录复制正常」→ v7 的 `prefix + 字面斜杠` 修法生效，`下载/目录名/子目录/文件` 落盘正确；
- 「复制单独目录时，会输出没有目录内容可同步」→ 见下面「问题一」；
- 「日志文件没有输出」→ 见下面「问题二」。

## 问题一：复制普通文件时误弹「没有目录内容可同步」

`/request_file` 的返回体里，`manifest_batch_url` 只有**带目录**时才给。v7 在
「没拿到这个地址」的分支里无条件弹一句「没有目录内容可同步……」，于是复制
普通文件（本来就没有目录）也会弹，纯噪音。

修法：返回体多给一个 **`folder_count`**（这次带了几个目录），接收端先判断：

```
目录数 = 响应.folder_count
如果 目录数 > 0：
    如果 有 manifest_batch_error → 原样显示服务端的说明（多台电脑各登记了目录）
    否则 → 提示「电脑端版本旧，请升到 1.12.7」
否则：
    （老服务端没有 folder_count）如果 类型 == folder → 同样的提示
    仍然不成立 → 静默
```

`folder_count == 0` 时什么都不说，只留结尾那条「同步完成」。

## 问题二：日志为什么一条都没写出来

v7 用「存储到文件」把文本写进 `下载/SyncClipboard-调试.log`，`检查` 逻辑也加了，
结果真机上一个文件都没有 —— 连「保存失败」通知都没弹（因为 v7 把那层校验去掉了）。
结论：**这个动作保存纯文本时会静默不落盘**（保存下载下来的文件对象是正常的，
v6 的文件确实落地了，只是名字错）。

所以 v8 换成 **HTTP 推送**：

```
每个节点：日志 += 一行  →  POST /ios_log  { "log": 完整日志 }
服务端：覆盖写 <项目>/log/ios_shortcut.log
```

- 走的是和 `/request_file` 一样的「获取 URL 内容 + JSON body」，这条通道已经跑通无数次；
- 每次推的是**累积后的完整日志**，服务端覆盖写：崩在哪一步，电脑上那份就停在哪一步；
- 循环里每处理完一个文件推一次，第一条出问题的记录一定留得住；
- 结尾仍会尽力存一份 `SyncClipboard-调试.log` 到手机「下载」，方便自己翻；存不上也不影响排查。

**日志现在在电脑上**：`<SyncClipboard 项目目录>/log/ios_shortcut.log`，跑完直接看这个文件。

日志大概长这样：

```
SyncClipboard 同步日志
=== SyncClipboard 同步开始 ===
① 服务器 http://192.168.1.24:8000 ｜ 设备 iPhone
② 响应 type=folder
③ 待下载 1 项
④ 清单 课程 ｜ 5 个文件 ｜ 空目录 1
· a.txt ｜ dir=课程/子目录/ ｜ prefix=课程/子目录
   OK 写入 课程/子目录/a.txt
· readme.txt ｜ dir=课程/ ｜ prefix=课程
   !! 保存失败（动作输出为空，文件没落地）readme.txt
⑤ 同步结束：5 个文件
```

## 仍然存在的限制

- **空目录**建不出来（没有文件就没有落点），结尾会提示「N 个空目录没有文件可写」。
- 文件多时每个文件一次下载 + 一次日志推送，会慢；清单超 20000 条会截断并提示拆目录。
- 日志每节点一推是**全量重发**，文件数上千时上行量会明显变大（正常几十个文件无感）。
