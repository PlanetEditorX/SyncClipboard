# SyncClipboard

## 简介

SyncClipboard 是一个跨设备实时同步剪贴板内容的工具，支持**文本**、**图片**、**文件**等多种数据类型。该项目旨在解决 Windows 电脑、Android 设备与 iOS 18 手机在同一局域网内的剪贴板共享需求，通过高效的实时同步机制为用户提供无缝的跨设备体验。

- **文本同步**：任意一端复制，其他设备自动更新剪贴板（实时）。
- **文件/图片传输**：手机可按需从电脑拉取文件，也可主动发送文件到电脑保存。

---

## 功能说明

| 功能 | 触发方式 | 行为 | 状态 |
|------|---------|------|------|
| 1. 文本全端实时同步 | 任意客户端复制文本 | 服务器中转，其他客户端自动拉取并写入剪贴板 | ✅ |
| 2. 服务端本机文件 → 手机 | 手机手动运行「获取同步」 | 返回文件流或目录清单，接收端逐文件下载；取完或到期后自动撤销共享 | ✅ |
| 3. 手机文件上传至服务器 | 手机手动运行「推送同步」 | 保存到配置的下载目录，完成后自动定位到文件 | ✅ |
| 4. 其他电脑文件 → 手机 | 手机手动运行「获取同步」 | 服务器下发源电脑的下载地址，手机直连下载 | ✅ |
| 5. 电脑A文件 → 电脑B | 点击托盘图标或通知后手动拉取 | 同手机拉取，中断可按 HTTP Range 续传 | ✅ |

**注意**：多台 Windows 电脑间**不进行文件剪贴板自动同步**。原因：若任意一端复制文件就要上传至服务器并分发给所有电脑，频繁复制时会产生大量不必要的磁盘读写和网络开销，而实际可能根本不会使用这些文件。文本同步已覆盖日常需求，文件传输仅设计为主动按需获取，手机运行快捷指令后手动拉取文件，电脑其它客户端通过点击弹窗或点击任务栏图标左键后手动拉取文件。单文件下载一次后共享即撤销；目录按清单逐文件下载，取完或到期（`file_share_ttl_minutes`，默认 30 分钟）才撤销。

## 使用

### 电脑端

1. 启动 SyncClipboard（托盘面板），按需开启「本机服务器」与「同步客户端」。
2. 在面板打开「本机服务器」时，会自动把「连接设置 → 服务器地址」改成 `127.0.0.1` 并重启客户端；关闭服务器不会自动改回，需要连回远端服务器时手动填回地址并保存。
3. 复制任意文字，其他电脑客户端和手机都会在几秒内自动同步。
4. 复制文件后（在任意电脑上）：
   - 服务器本机文件：手机直接拉取即可下载。
   - 其他电脑文件：手机拉取时会自动跳转到源电脑下载。
5. 手机发送的文件默认保存到客户端配置的 `save_path` 目录下。
6. 点击任务栏图标左键，会自动同步下载其它客户端上传的文件，没有文件就同步最新的文字内容。
7. 排查问题时，主界面「运行日志」区可分别查看**服务日志**、**客户端日志**和**界面日志**（文件在 `log/` 目录）；打开后每 2 秒自动刷新，窗口关闭即停止读取，不在后台占用资源。
8. 退出有两个入口：托盘菜单的「退出」，或面板「快速操作 → 退出程序」。都会先停掉本机服务器与同步客户端（保留开关状态，下次启动照旧恢复）再退出；万一某个环节卡住，15 秒后强制结束进程，不会再出现「托盘图标没了、任务管理器里还有进程」。
9. 托盘菜单的「重启程序」= 退出 + 重新拉起：先起新实例（自动等旧实例退干净再接管，不会被单实例判定当成重复启动丢掉），再按上面的退出流程收尾；服务开关、窗口是否收在托盘里都沿用当前状态。

### 手机端

- **文字同步**（iOS）：打开设置了自动化的 App（如微信、浏览器）时，快捷指令自动运行，拉取最新文本并写入剪贴板；手机复制文字也会自动推送到电脑。
- **获取同步**：手动点击控制中心的「获取同步」，从电脑拉取最新文字、文件或整个目录。
- **推送同步**：手动点击「推送同步」，把手机上的文字 / 文件 / 图片发送到电脑下载目录。
- **短信同步**：收到验证码短信时自动抽码写入电脑剪贴板（自动化需单独添加）。
- Android 端：见下方「手机配置 → Android端」。

## 部署

### 系统要求

- **操作系统**：Windows 10+，iOS 18（Android 客户端见 `android/README.md`）。
- **网络**：所有设备处于同一局域网。

### 从源码运行（Windows）

```bash
pip install -r requirements.txt
python gui/run.py       # 托盘 + 面板，按上次的开关状态拉起服务端/客户端（推荐）
python server/run.py    # 只跑中心服务端
python client/run.py    # 只跑剪贴板客户端
```

配置文件首次运行会自动生成在 `config/`，模板见 `config/example/`。

### Docker 部署示例

可以使用 Docker 或 Docker Compose 启动服务端，并挂载本地配置、日志和 latest 数据目录：

```yaml
services:
  syncclipboard-server:
    image: yexundao/syncclipboard-server:latest
    container_name: syncclipboard-server
    restart: always
    ports:
      - "8000:8000"
    volumes:
      - ./config:/app/config
      - ./log:/app/log
      - ./latest:/app/latest
      - ./downloads:/app/downloads
    environment:
      - PORT=8000
      - TZ=Asia/Shanghai
```

`./config`、`./log`、`./latest` 分别保存配置、日志和共享状态；**`./downloads` 必须挂**：手机上传的文件默认落在容器的 `/app/downloads`（`SAVE_PATH`），不挂载则容器重建后文件全丢。镜像内已装 `tzdata`，`TZ` 才会真正生效；`PORT` 会同时写回 `app.config['port']`，保证 `/clients/online` 下发的中转地址端口与实际监听一致。换宿主端口时记得把 `PORT` 一起改。镜像带 `/status` 健康检查。

构建镜像时上下文是仓库根目录：

```bash
docker build -f docker/Dockerfile -t syncclipboard-server .
```

根目录的 `.dockerignore` 会排除 `.git`、`.venv`、运行期状态文件和 `config/*.json`（避免把本机 IP 和密钥打进镜像）。

### 统一鉴权契约

**所有端、所有 HTTP 请求一律在请求头带 `key`**，与 `server_config.json` 的 `key` 一致：

- 中心服务端：`require_key()` 是全站唯一入口，18 个路由共用；
- 电脑端 FileServer：除 `/ping` 探活外，全部路由（含 `/file`、`/manifest`、`/files`、`/check`）都校验；
- iOS 快捷指令：`/request_file`、每个下载地址、每份目录清单都带 `key`；
- Android：出站请求与入站回调都带 `key`，不再靠「来源 IP 等于服务器」免密放行。

JSON body 里的 `key` 与 `?key=` 仍被同一个校验函数接受，但只是等价入口，新接入方请只用请求头。升级后请把**所有端一起升级**：只升级服务端而留着旧快捷指令/旧 APK，下载地址会拿到 403。

统一鉴权契约时同步重生成了 4 份 `shortcuts/*/*-unsigned.plist` 与对应的 `.shortcut` 签名产物（文件路径见「手机配置」）。`.shortcut` 是 Apple 签名产物，本机无法自行重签；改动 plist 参数后需重新签名再导入 iOS。旧版 `.shortcut` 导入后下载会 403。

### 电脑配置

1. 从 [Releases](https://github.com/PlanetEditorX/SyncClipboard/releases) 下载 `SyncClipboard-Windows-<tag>.zip`（例如 `SyncClipboard-Windows-v1.12.27.zip`），解压到任意目录后运行 `SyncClipboard.exe`。旧版可直接解压覆盖：安装包只带 `config/example` 模板，不会覆盖已有的 `config/*.json` 个人配置与 `log/` 日志。
2. 解压后编辑 `server_config.json`：

   ```json
   {
       "key": "123456",
       "port": 8000,
       "local_name": "Server"
   }
   ```

3. 编辑 `client_config.json`，保证 `key`、`server_host`、`server_port` 与服务器一致，`file_server_port` 可自定义（默认 8899）：

   ```json
   {
       "server_host": "127.0.0.1",
       "server_port": 8000,
       "key": "123456",
       "local_name": "PC-01",
       "file_server_port": 8899
   }
   ```

4. 在面板按需开启「本机服务器」「同步客户端」和开机启动。开启本机服务器会自动把 `server_host` 写为 `127.0.0.1`（见下节）。

**多 Windows + 单 iOS 文字同步**：每台电脑使用不同的 `local_name` 即可，任意一端复制文字，其他端自动同步。

### 同步控制（面板）

主界面「同步控制」卡片可以精细控制两端行为，保存后客户端（必要时连同服务器）会自动重启生效：

| 选项 | 说明 | 配置字段 |
| --- | --- | --- |
| 文字同步 | 双向 / 只发送 / 只接收。只接收时本机不会再上传剪贴板，只发送时不会写回远端文字 | `text_sync_mode` |
| 文件同步 | 双向 / 只发送 / 只接收。只发送时不再提示远端发布的文件，只接收时不再共享本地文件 | `file_sync_mode` |
| 同步复制的文件夹 | 关闭后复制文件夹不会被同步；开启时按清单逐文件传输，不打包压缩 | `folder_sync_enabled` |
| 目录大小阈值 | 默认 10 GB。复制时统计目录总大小，超过阈值在右下角弹通知确认，批准后才登记共享。配置键名沿用历史命名 `folder_zip_confirm_gb`（目录已不打包，改名会破坏老配置） | `folder_zip_confirm_gb` |
| 目录文件数阈值 | 默认 3000 个。复制时统计文件数，超过阈值同样弹通知确认；两个阈值任一超限即询问。上限 20000，与清单硬上限 `MANIFEST_MAX_ENTRIES` 对齐 | `folder_file_count_confirm` |
| 确认弹窗持续时间 | 默认 15 秒。通知在右下角带「允许共享 / 暂不共享」按钮，到点没点允许就按不共享处理：既不登记也不上报，客户端根本看不到这个目录。范围 3~300 秒 | `folder_confirm_timeout_seconds` |
| 共享存活时间 | 默认 30 分钟，是「从复制到首次获取」的最长等待窗口：服务端到期丢弃记录，本机撤销共享登记。目录开始下载后每次成功请求自动续期，逐文件下载不会被中途 404；到期只取消登记，不删除原文件 | `file_share_ttl_minutes` |
| 下载完成后自动取消共享 | 开启（默认，`1` 次）= 有设备完整下载一次就撤销登记；关闭 = 存活期内所有已配对设备都能获取。`0` 不限制，`1`~`99` 表示允许完成该次数**完整下载**的设备数；「完整」以发送端实际发出的字节数判定，达到后立即取消登记 | `share_download_limit` |
| 服务器派发时也弹通知 | 默认开启。手机把内容推给本机服务器时本来就会弹「剪贴板更新」；开启后，服务器再把内容派发到本机客户端时同样提醒（默认开启，关掉后仍然同步、只是不弹）。两个进程共用一份通知账本，同一条记录只响一次 | `notify_remote_push` |

「确认弹窗持续时间」走的是 Windows 通知（与「手机文件已保存」同一条通道），所以复制目录的线程会一直等到出结果或超时；通知发不出来时（非 Windows / 缺少通知支持）退回带同样超时的原生对话框，超时同样按不共享处理。

示例 `client_config.json`（旧版本缺少这些字段时会自动补默认值）：

```json
{
    "server_host": "127.0.0.1",
    "server_port": 8000,
    "key": "123456",
    "local_name": "PC-01",
    "file_server_port": 8899,
    "save_path": "D:/Downloads",
    "text_sync_mode": "both",
    "file_sync_mode": "both",
    "folder_sync_enabled": true,
    "folder_zip_confirm_gb": 10,
    "folder_file_count_confirm": 3000,
    "file_share_ttl_minutes": 30,
    "share_download_limit": 1,
    "folder_confirm_timeout_seconds": 15,
    "notify_remote_push": true,
    "update_source": "direct",
    "update_mirror_prefix": "https://gh-proxy.com",
    "update_proxy": ""
}
```

`file_share_ttl_minutes` 会同时写入 `server_config.json`，Docker/Linux 部署可只改服务器配置里的这一项。目录的两个确认阈值只作用于发送端（复制那一刻），确认通知会写明批准后共享存活期内已配对设备均可获取；不批准就不登记、不上报，客户端自然取不到。

**「一次下载」怎么算**：不看谁取了清单，看**发送端实际发出了多少字节**。普通文件：`/file/<id>` 的流式响应发满整个文件；目录：`/manifest` 清单里列出的每个成员文件都发满各自体积（`build_manifest` 的 `size`），才算一次完整下载。清单被截断时按实际列出的条目判定，空目录取完清单即算完成。响应体在 `FileServer` 里逐 chunk 累加，按「共享 + 设备 + 相对路径」去重记进度：同一设备重试 / 断点续传不虚增进度，也不会被中途的重复请求提前判完成。接收端（含 iOS 快捷指令）不需要回报任何东西。

按设备（设备名 + IP）计次，同一设备重复下载不重复计入。`N>0` 时第一个设备来取清单 / 文件即**预留名额**，避免「A 还在下 100MB，B 也进来下完」造成超发；达到第 N 次完整下载、且已无其它响应在传输时立即撤销登记，收尾扫描再兜底几秒。之后新设备取清单会得到 `410`，共享已被撤销则 `404`。传输中断会归还该设备的名额方便重试；僵死会话由共享存活时间兜底。次数用尽的共享不会再被 `reannounce_shares` 重新广播。

次数限制开启时，目录成员文件请求也只放行「已准入会话」的设备，避免拿到 URL 后绕过检查逐个拉走；不限制时保留老客户端直接拼成员 URL 的兼容路径。统计放在**发送端本机文件服务**上：服务端 `/request_file` 只转发 URL、不中转字节流，一次性消费也管不住持有链接的重复拉取，而所有下载最终都要访问 `FileServer`。

「快速操作 → 查看下载记录」是一个**每秒自动刷新**的非模态窗口：上半张表按设备显示「已发字节 / 共享总大小 / 进度 / 文件数 / 状态 / 操作」，下半张表是最近 200 条开始 / 取清单 / 完成 / 中断 / 拒绝 / 取消事件。刷新保留滚动位置与当前行，可以一边传一边盯着看；有「暂停刷新 / 立即刷新」按钮，关掉窗口即停止轮询。记录只留在客户端内存，重启后清空，原文件永远不会被删除。

「操作」列的按钮就地收尾：传输中的行显示「取消传输」，点确认后发送端立刻停止继续发送（正在传的响应在下一个数据块处收尾），并把该设备记进撤销表——它之后再拿旧链接只会收到 403，不能靠重试把剩下的拉完；多台设备同时在取时只掐被点的那一台，别的设备不受影响。已完成的行显示「取消共享」，只撤销登记，已完成的下载记录照样保留。两种取消都会在下半张表留一条「手动取消」事件。

「快速操作 → 客户端管理」是一个**每 3 秒自动刷新**的非模态窗口，列出服务端登记过的全部设备：名字（后缀标「本机」或「服务器」）、系统、IP、推送端口、推送次数、成功次数、推送率、上次推送、上次连接、在线状态，每行两个按钮：「移除」和「黑名单 / 解除」。**「本机」由看窗口的这台电脑自己判定**，服务端下发的 `is_server` 只标「服务器」——所以在另一台电脑上打开，不会把服务器误认成自己。数据来自 `GET /clients`（带 `probe=1` 时服务端并发 ping 一遍看谁在线，结果缓存 5 秒，行里带 `blacklisted` 标记），移除走 `POST /clients/delete`，黑名单走 `POST /clients/blacklist`。

两个统计口径：**推送次数**是服务端为这台设备「试图投递」的次数，离线、端口不通也算一次；**成功**只认内容真的到了设备手上（主动推送看 HTTP 200，iOS 这类轮询型要它真把内容取走才算）。**推送率刻意不上色**：复制是高频常规操作，同步要等设备醒来才发生，用久了几乎必然全红——那是使用节奏，不是故障。判断设备好不好用请看「状态」和「上次连接」；服务端探不出在线与否的设备（iOS、还没上报推送端口）状态一律显示「轮询」而不是「未知」，汇总行的计数也跟着写「轮询 N」；汇总行里的比例叫**推送率**（分母是推送次数）。

**「移除」只是从派发列表删掉这条记录和统计**：设备只要还在跑，下一次请求就会自动登记回来，又开始收推送——它是「暂时别发给它」，不是拉黑。真要拦住一台设备用每行的**「黑名单」**：加进去之后它发来的同步请求直接 403 拒绝、注册也不收、派发列表更不会给它推送；只有在这个面板上解除黑名单才恢复。黑名单持久化在 `config/blacklist.json`，服务端重启依然有效；管理面板自己的接口不受拦截，否则加黑之后就再也解不开了。

**只有服务器和客户端在同一台机器上才能修改名单。** `GET /clients`（含只读探测）对任何持有密钥的客户端开放，但 `POST /clients/delete` 和 `POST /clients/blacklist` 会在服务端核对请求来源：回环地址或服务器自己的任一网卡地址才算本机；从另一台电脑连过来即使密钥正确也返回 403。面板按响应里的 `can_manage` 把「移除 / 黑名单 / 清空列表」全部置灰并说明原因，切换连接地址后会先收回权限、等新服务器确认再放开。在服务器本机用 `127.0.0.1` 或它自己的局域网 IP 连接都算同机。

Docker 那种只跑服务端、本机没有面板的部署，只能手动编辑挂载出来的 `config/client_ip.json`（名单，下次请求重新载入即生效）和 `config/blacklist.json`（黑名单，改完需重启服务端容器才会载入）。

> 默认 `1` 次：任意设备完整下载一次后立即撤销登记（阅后即焚）。想让多台设备在存活期内各取一次，把「下载完成后自动取消共享」关掉（写入 `0`），或在次数框里填更大的值。

### 服务开关与连接地址

| 操作 | 自动行为 |
| --- | --- |
| 打开「本机服务器」（面板或托盘） | 把 `client_config.json` 的 `server_host` 写为 `127.0.0.1`，并把面板里的「共享密钥」同步写入 `server_config.json`；面板「服务器地址」同步刷新，正在运行的客户端自动重启，连上刚启动的本机服务端 |
| 关闭「本机服务器」 | 只停服务端进程，**不改动**连接地址和密钥；要连回局域网里另一台服务器，在「连接设置」手动改地址并保存 |
| 地址本来就是 `127.0.0.1` | 不写配置、不重启客户端，避免无谓的进程抖动 |

服务端始终监听 `0.0.0.0`，因此手机和其他电脑仍通过本机 LAN IP 接入；`127.0.0.1` 只决定**这台电脑上的客户端**连到哪台服务器。首次生成的 `client_config.json` 默认就是 `127.0.0.1`。

**共享密钥改的是谁**（「连接设置 → 共享密钥」，输入框下方会跟着地址和服务状态实时提示）：
- **本机服务器已开启**（无论客户端填的是 `127.0.0.1` 还是本机 LAN IP）：这个密钥同时是本机服务器的密钥。保存时 `client_config.json` 与 `server_config.json` 一起改，服务端自动重启；手机等其他设备也要同步改成新密钥。
- **只开客户端、地址指向别的机器**：这里只是访问对方服务器的凭证，只写客户端配置；本机服务器沿用 `server_config.json` 里自己的密钥，两边可以不同。
- **地址指向本机但服务器没开**：两边一起写，下次启动本机服务器即生效。

托盘的「打开客户端配置 / 打开服务器配置」分别打开两个 json：系统没给 `.json` 关联程序时会自动退回记事本；文件还没生成会明确提示，不再像点了没反应。

### 手机配置

#### iOS端

1. **安装 Actions**（用于检测主机可达性，避免快捷指令因网络异常报错）
   - 如果未安装过，可能需要借助 [ipatool](https://github.com/majd/ipatool) 购买历史版本。
   - 若实在无法安装，可手动删除快捷指令中涉及 Actions 的部分。

2. **添加快捷指令**（4 条，直接导入仓库里的签名文件，不要再找旧的在线分享链接）

   | 快捷指令 | 文件 | 作用 |
   | --- | --- | --- |
   | 文字同步 | [`shortcuts/文字同步/文字同步.shortcut`](shortcuts/文字同步/文字同步.shortcut) | 常驻轮询，双向同步剪贴板文字 |
   | 推送同步 | [`shortcuts/推送同步/推送同步.shortcut`](shortcuts/推送同步/推送同步.shortcut) | 把剪贴板内容（文字 / 文件）推给电脑 |
   | 获取同步 | [`shortcuts/获取同步/获取同步.shortcut`](shortcuts/获取同步/获取同步.shortcut) | 拉取文字、文件、目录（按合并清单逐文件落地） |
   | 短信同步 | [`shortcuts/短信同步/短信同步.shortcut`](shortcuts/短信同步/短信同步.shortcut) | 从验证码短信里抽数字推到电脑剪贴板 |

   - 每条指令的源文件是同目录下的 `*-unsigned.plist`，可用 `shortcuts/<名字>/build.py` 重建；改参数后用 `shortcuts/lib/sign.py` 重签。
   - 4 条 `.shortcut` 已按统一鉴权契约重新签名，所有请求一律带 `key` 请求头；旧版产物导入后下载会 403，务必整组替换。
   - 离线整包分发可用 Release 里的 `SyncClipboard-iOS-Shortcuts-<tag>.zip`，内容与上述 4 个文件同源；导入后在每条指令的「配置」词典里改主机、端口、密钥。

3. **修改快捷指令参数**
   - 主机地址、密钥、端口，与服务器配置保持一致。
   - 停止自动更新的电量阈值（如 40%），低于该电量不执行同步。
   - 循环时间策略：
     - 时间1：打开 App 前 1 分钟内的等待间隔
     - 时间2：1～3 分钟内的等待间隔
     - 时间3：3 分钟后的等待间隔
     （刚打开 App 时高频同步，后续逐步降低频率以省电）

4. **创建自动化**
   - 类型：App → 打开时运行快捷指令
   - 设置为“立即运行”，关闭“运行时通知”
   - 选择常用 App（如微信、浏览器等），运行「文字同步」快捷指令

5. **控制中心**
   - 添加「推送同步」和「获取同步」快捷指令，方便手动触发文件传输。

6. **关闭多余通知**
   - 进入 设置 → 屏幕使用时间 → 查看所有 App 与网站活动 → 通知
   - 将快捷指令的通知改为仅横幅，关闭其他提醒。

#### Android端
1. **安装SyncClipboard-Android**
 - 配置：主机、密钥、本机监听端口、设备名称、下载路径
 - 开启无障碍权限、悬浮窗权限

2. **安卓互联效果和限制**
   - 安卓、Windows和iOS客户端复制文字后，通过服务器正常同步文字到其它所有客户端。
   - Windows复制文件后，其它Windows客户端和安卓客户端上都会显示文件发布的通知，Windows客户端可直接点击通知进行下载，通知消失后也能通过点击图标进行下载，任意一端下载后取消文件共享。安卓点击通知进行下载，下载到之前指定的目录下，如果没有点击通知，60秒后通知将会被自动清理。
   - **目录不打包**：复制文件夹时一次遍历统计总大小与文件数并登记共享（`文件夹名`、原始体积），接收端来取时按清单逐文件下载；两个阈值任一超限会先在发送端右下角弹通知确认，点「允许共享」才登记，超时按不共享处理。不产生任何临时压缩包，因此本地复制大目录但不需要传给别的设备时零额外开销。
   - 对方来取目录时先取清单（`root` / `entries[{path, dir, name, size, url}]`），再按清单逐项 `GET /file/<file_id>/<相对路径>`，本地按相对路径重建目录结构。**不走归档格式** —— iOS 的「解压缩」会把包内目录摊平，那是 v1.12.3 以前所有文件堆在同一个目录的根因。
   - 手机上（iOS 快捷指令）只取**合并清单** `GET /manifest/batch?ids=d1,d2`：把多个目录的文件摊平成一张表，`dir` 已含「目录名/」前缀。因为「重复每一项」嵌两层时内层取不到值（v1.12.4 的真机问题），接收端全程只能跑一层循环。
   - Android 客户端直接对接新协议：识别 `kind=folder`，取 `manifest_batch_url`（多来源时逐目录取 `manifest_url`），按 `prefix` 逐文件下载并重建子目录；下载失败的文件写回待办队列，下一轮轮询自动重试，不会因 `/request_file` 一次性消费而永久丢失。入站回调只认请求头 `key`，已移除「服务器 IP 免密上传」开关。
   - 单文件下载失败只跳过该文件，其余继续；整份共享在接收端取完、到期或重新复制时才撤销。Windows 端下载中断会自动重试 3 次，续传用 HTTP Range 从断点接着来。
   - 下载不再询问保存位置：直接存到面板配置的下载目录（重名自动加 `(1)`），完成后资源管理器自动定位到文件；手机传到电脑的文件，点击通知同样会打开所在文件夹。

## 其他

### 运行失败排查

- 手动执行一次快捷指令，观察是否正常。
- 查看电脑客户端日志（`log/client.log`）或手机快捷指令运行日志。
- 快捷指令自动停止的可能原因：
  - 非手动运行（自动化未触发）
  - 电量低于设置阈值
  - 不在设置的 App 界面（如停留在桌面）
  - 服务器不可达（Actions 检测失败）

### 更新版本

在仓库中打标签并推送：

```bash
git tag -a v1.0.0 -m "Release 1.0.0"
git push origin v1.0.0
```

推 tag 会触发 `Build and Release`，一次产出三样东西并挂到同一条 Release：

- `SyncClipboard-Windows-<tag>.zip`；
- `SyncClipboard-iOS-Shortcuts-<tag>.zip`（4 条已签名快捷指令）；
- `SyncClipboard-Android-<tag>.apk` —— **每次发版都重新构建**，即使 `android/` 没有任何改动，保证三个平台的版本号永远一致。APK 构建失败不会阻塞 Windows 包发版（下载那步会跳过并留警告）；需要单独重出 APK 时，在 Actions 页手动运行 `Build Android`。

#### 面板里的「检查更新」

底部「更新源」三选一，改完保存即生效（只影响更新检查与下载，不影响同步本身）：

| 档位 | 行为 |
| --- | --- |
| GitHub 直连 | 直接访问 `api.github.com` 与 Release 下载地址 |
| 镜像加速 | 请求地址改写成「镜像前缀 + 原始地址」，检查与下载都走镜像。内置 gh-proxy / ghfast / ghproxy / hub.gitmirror 等几个公共前缀，下拉里可以直接选，也可以自己填；镜像失效会自动退回直连一次。刻意不放 jsDelivr 系（`cdn.jsdelivr.net` 等）——它们只能取仓库 raw 文件，代理不了 Release 的 zip 和 API |
| 手动代理 | 只给请求挂 HTTP/HTTPS 代理（如 `http://127.0.0.1:7890`），URL 不变。**不支持 SOCKS5**：那要额外装 PySocks，安装包会变大 |

下载过程中按钮会变成「取消下载」，点一下立即中断并把临时目录（`%TEMP%\syncclipboard_update_*`）整个删掉，状态回到可以重新下载。已就绪但没重启时，临时目录会保留到更新完成或下次取消。

#### 面板里的「查看仓库」

底部「检查更新」左边还有一个「查看仓库」（托盘菜单里是「访问项目仓库」）：点一下就用系统默认浏览器打开 <https://github.com/PlanetEditorX/SyncClipboard>。地址只在 `common/updater.py` 的 `REPOSITORY` / `PROJECT_PAGE` 里维护一份，改动仓库时不用满项目找链接。打不开浏览器（没装默认浏览器、Shell 关联坏了）会弹窗并把地址一起显示出来，可以直接复制。

## 数据流简图

```
[电脑A]       --复制文本--> 服务器 <--轮询--> [电脑B]  (文本实时同步)
[手机]        --复制文本--> 服务器 --> 电脑自动拉取
[电脑A]       --复制文件--> 服务器 (记录元数据)
[手机/电脑B]  --请求文件--> 服务器
                ├── 文件在本地? 直接返回文件流
                └── 文件在远端? 返回跳转 --> [从源电脑A下载]
                    (任意客户端下载一次后共享取消)
[手机]        --上传文件--> 服务器保存到本地目录
```
